# Routing and Session Preferences — 需求规格

## 概述

让 BYZ 在当前会话中识别常见任务形态，并应用用户以自然语言指定的协作偏好；不自动切换模型、workflow 或 skill，不写入长期记忆。

## 项目信息

- 项目名: pi-monorepo
- 架构类型: npm workspace monorepo；BYZ CLI 包装层
- 交付形态: 本地终端 CLI

## 范围

**做：** 当前轮任务分类、路由说明、路由失败降级、当前会话的主动程度与交付形态偏好。

**不做：** 自动模型/workflow/skill 切换、偏好持久化、长期记忆、项目治理、外部副作用授权。

## 用户故事

- 作为用户，我想直接说“查一下这个链接”或“先给三个方向”，以便 BYZ 按目标协作而非要求我选择内部模式。
- 作为用户，我想说“直接做”“少问一点”或“关键动作先问我”，以便当前会话的主动程度符合预期。
- 作为用户，我想在能力或资料不足时知道缺什么和可用替代，而不是得到伪装的完成结果。

## 功能需求

1. [F-001] BYZ 必须将当前请求分类为 research、creative、bug-fix、feature、project-recovery 或 general；分类仅在当前轮使用且默认不可见。
2. [F-002] 对明确的自然语言控制短语，BYZ 必须在当前会话应用对应偏好：`直接做`、`少问一点`、`关键动作先问我`、`先给三个方向`、`展开细节`。
3. [F-003] 路由结果必须通过稳定的协作提示影响本轮处理方式，不得自动选择或切换模型、workflow、skill，也不得新增网络请求。
4. [F-004] 对缺少必要输入、访问失败或能力不可用的请求，BYZ 必须说明未完成的部分与至少一个可行降级路径。
5. [F-005] 用户请求详情时，BYZ 才可展示本轮任务类别和已生效的会话偏好；默认普通输出不得主动显示它们。
6. [F-006] 会话结束、重载或新会话开始后，路由状态与偏好必须重置；不得写入 `.byz`、环境变量或工作区文件。

## 非功能需求

- 兼容性: M1 对话壳、Fast、Prewalk、workflow、非交互 CLI 参数保持现有行为。
- 安全: 路由不得将用户内容写入持久存储、日志摘要、环境变量或 shell 命令。
- 性能: 任务分类为本地纯函数；不得增加模型调用或网络请求。
- 可访问性: 路由失败和偏好状态必须用文字表达，不能依赖颜色。

## 验收标准

- [ ] [AC-001] 常见研究、创作、缺陷、新功能和恢复请求分别被确定性分类；未匹配请求归为 general。
- [ ] [AC-002] 控制短语在当前会话即时生效，并影响后续路由提示；新会话与 reload 后恢复默认值。
- [ ] [AC-003] 路由不会修改当前模型、thinking、workflow 资源、skill 资源或持久化文件。
- [ ] [AC-004] 缺少输入或能力不可用时，用户可见输出明确包含未完成部分和替代路径。
- [ ] [AC-005] 默认输出不显示类别或偏好；输入“展开细节”后可查看二者。

## 依赖

- M1 `conversation-shell` 的 conversation extension 与展示适配 API。
- bundled runtime 的 `before_agent_start` 生命周期事件。

## 开放问题

- 无。M2 偏好仅当前会话有效；持久化属于 M3。
