# BYZ 对话式 Agent —— 产品需求文档（PRD）

> 成熟度：L3 可落地规格 ｜ 类型：B CLI / 开发者工具
>
> 一句话：BYZ 是面向独立创作者与创业者的本机优先 AI 工作伙伴；用户用自然语言交代任何任务，BYZ 自适应调用能力、记住协作偏好，并只在真正高影响的节点请求确认。

## 1. 问题陈述

独立创作者需要研究、设计、写作、开发和长期项目交付能力，但不应先理解模型、工具、skill 或固定工作流。传统终端把内部步骤、日志和配置暴露给用户；固定项目流程又会限制研究、创作等轻量任务。

BYZ 应把复杂能力藏在后台，前台保持像可靠协作伙伴的自然对话：能安全完成就直接完成；会改变承诺或产生不可逆影响时，清楚说明影响并等待决定。

## 2. 目标用户

| 角色 | 描述 | 主要诉求 |
| --- | --- | --- |
| 独立创作者/创业者 | 一人主导研究、产品、内容和软件交付 | 一个入口处理不同任务，不学习工具链，不失去控制 |
| 长期项目负责人 | 有持续演进的代码、内容或产品项目 | 记住上下文、决策和下一步，可恢复、可追溯 |

## 3. 核心方案

```text
用户自然语言提出目标
        ↓
BYZ 识别任务类型与风险
        ↓
后台调用适合的能力
        ↓
用自然语言交付结果、产物或必要决策
        ↓
按规则写入本机可控记忆或项目状态
```

BYZ 是唯一用户可见产品。模型、工具、技能、执行引擎和内部日志都是实现细节，默认不出现在对话中。

## 4. 核心用户故事

### US-1：通用任务入口

作为独立创作者，我想用一句自然语言提出研究、设计、写作或开发需求，以便不必先选择模式或技能。

**验收标准：**

- [ ] 用户输入任意任务后，BYZ 先以一句自然语言确认理解或直接行动。
- [ ] BYZ 不要求用户先选择模型、skill、工作流或技术栈。
- [ ] 可安全完成的任务在一次对话内给出首次有效结果。
- [ ] 默认输出不展示内部推理、能力名称、工具调用或步骤计数。

### US-2：主动但可控的协作

作为用户，我想让 BYZ 能判断的事情直接做完，但在高影响动作前先问我，以便减少摩擦又不失控。

**验收标准：**

- [ ] 阅读、总结、分析、生成草稿等低风险任务默认直接执行。
- [ ] 删除重要内容、外部发送、发布、支付、部署等动作必须先确认。
- [ ] 用户可说“少问一点”“关键动作先问我”“直接做”“先给三个方向”，当轮立即生效。
- [ ] 用户可将互动偏好保存为后续默认行为。

### US-3：自然过程反馈

作为用户，我想在长任务中知道是否需要等待或介入，但不想看滚动日志，以便保持对话感。

**验收标准：**

- [ ] 30 秒内没有可见结果时，BYZ 最多给一次简短进展说明。
- [ ] 正常执行过程不连续输出“正在思考”“正在调用”“步骤 X/Y”。
- [ ] 失败说明必须包含业务影响、已采取处理和是否需要用户决定。
- [ ] 用户输入“展开细节”后才显示技术证据、日志或 diff。

### US-4：本机可控记忆

作为用户，我想让 BYZ 记住互动偏好和长期项目上下文，同时能随时查看、修改与删除，以便建立连续协作但不被隐形画像。

**验收标准：**

- [ ] 用户输入“你记住了什么”后，BYZ 按类别展示记忆及来源。
- [ ] 用户可说“忘掉这条”“清空这个项目记忆”。
- [ ] BYZ 不保存密钥、token、密码、Cookie 或未确认敏感信息。
- [ ] BYZ 使用历史项目记忆时，说明来源，例如“基于你上次确认的第一期范围”。

### US-5：按需项目治理

作为长期项目负责人，我想只在复杂项目中得到范围、验收与发布治理，以便轻量任务不受固定流程限制。

**验收标准：**

- [ ] 单次研究、总结、草稿与设计探索默认不建项目、不强制审批。
- [ ] 用户明确要求完整项目，或任务涉及多阶段、持久改动、交付承诺时，BYZ 升级为项目任务。
- [ ] 改变已确认目标、验收、成本、交付日期或交付形态时，BYZ 生成影响摘要并等待确认。
- [ ] 用户重新启动后，BYZ 能恢复最近项目或最近待决事项。

## 5. 功能需求

### FR-1：自然语言输入

```text
byz
byz "查阅这个 X 帖子并总结重点：https://…"
byz "为我的预约系统设计三个首页方向"
byz "修复当前项目的登录报错"
```

`byz` 进入连续对话，首屏为：

```text
BYZ

你想让我帮你做什么？
›
```

用户可用自然语言表达控制意图：`直接做`、`少问一点`、`关键动作先问我`、`继续`、`暂停`、`取消`、`总结一下`、`展开细节`、`你记住了什么`、`忘掉这条`。

### FR-2：任务路由

| 任务形态 | 前台表达 | 后台行为 |
| --- | --- | --- |
| 链接/社交帖子查阅 | “我来读一下，重点看主张、证据和遗漏。” | 使用可访问对应来源的能力 |
| 模糊创意/设计 | “我先整理一版可见骨架。” | 使用产品、设计或写作能力 |
| 可复现缺陷 | “我先复现并定位，确认后给你结果。” | 使用测试、定位与修复能力 |
| 新功能 | “我先确认目标与范围，再开始实现。” | 使用规格与开发能力 |
| 长期项目恢复 | “上次停在……，现在可以继续……” | 读取项目状态与本机记忆 |

路由失败时必须说明缺少的资料或可用降级路径，不得伪装已经完成。

### FR-3：风险与确认

| 动作 | 默认行为 |
| --- | --- |
| 阅读、总结、分析、生成草稿 | 直接执行 |
| 创建本地原型、修改工作区文件 | 直接执行后汇报 |
| 覆盖已有结果、删除重要文件 | 先确认 |
| 发送外部消息、发布、支付、部署 | 先确认 |
| 改变已批准范围、成本、日期或交付形态 | 先确认 |

确认提示必须包含：影响、推荐选择、替代选择、拒绝后的状态；默认不得展示底层命令。

示例：

```text
短信提醒会增加每月成本。

推荐：首期先使用邮件提醒；当前验收标准不变，交付可以继续。

[A] 接受推荐并继续
[B] 改用短信并生成范围变更
[C] 暂停讨论
```

同时接受自然语言，如“接受推荐”“改用短信”“暂停”。

### FR-4：本机记忆与项目状态

```text
.byz/
├── profile/
│   ├── interaction-preferences.json
│   └── user-memory.json
├── projects/
│   └── <project-id>/
│       ├── context.md
│       ├── decisions.jsonl
│       ├── specifications/
│       ├── evidence/
│       └── task-state.json
└── sessions/
    └── <session-id>.jsonl
```

```ts
interface MemoryEntry {
	id: string;
	category: "preference" | "project-fact" | "reference" | "decision";
	content: string;
	source: "user" | "approved-project";
	scope: "global" | "project";
	createdAt: string;
	updatedAt: string;
}
```

记忆只保存用户明确表达、已确认项目事实或用户主动保存的信息。

### FR-5：终端输出协议

所有输出最多包含四层：

1. 自然回应：理解或完成状态。
2. 核心结果：结论、产物或下一步。
3. 必要决定：仅当用户必须参与。
4. 按需详情：用户请求后显示。

终端视觉含义：

| 元素 | 含义 |
| --- | --- |
| 常规文字 | 对话与结果 |
| 绿色 | 已完成、可继续、已验证 |
| 橙色 | 当前需要用户决定 |
| 红色 | 无法自动恢复或有风险 |
| 灰色 | 可选提示、历史、技术详情 |

颜色不得是唯一信息载体。

### FR-6：任务升级规则

任务满足任一条件时升级为 `ProjectTask`：

- 用户明确说要做完整项目。
- 任务涉及多个阶段或持久文件改动。
- 任务需要范围、预算、发布或验收承诺。
- 用户主动要求规格、计划或可追溯记录。

`ProjectTask` 涉及已确认范围、成本、日期或交付形态时升级为 `GovernedTask`，等待确认。普通任务不进入此流程。

## 6. 边缘与异常状态

| 情况 | BYZ 行为 |
| --- | --- |
| 意图模糊但可合理假设 | 采用推荐假设，并允许用户纠正 |
| 意图模糊且会明显改变结果 | 只问一个最关键问题 |
| 外部访问失败 | 说明未取得的内容，不编造总结 |
| 能力不可用 | 使用可行降级路径，或说明用户需补充的材料 |
| 可自动修复的验证失败 | 自行修复与重试；不要求用户阅读错误详情 |
| 修复影响承诺或两次验证失败 | 明确升级为待决事项 |
| 用户中断后返回 | 用一句话恢复上次状态与可选下一步 |
| 多项目并行 | 显示当前项目；项目指代有歧义时才确认 |

## 7. 非目标

- 不让所有任务进入固定七步流程。
- 不要求用户学习模式、skill、模型或技术栈。
- 不默认展示内部推理、工具日志或步骤编号。
- 不在 MVP 中实现云同步、多人协作、组织权限或通用项目管理。
- 不静默积累无法查看和删除的长期用户画像。

## 8. MVP 里程碑

### M1：自然对话壳

- `byz` 统一入口。
- 自然语言回应与低噪声过程反馈。
- 终端输出协议与按需技术详情。

### M2：路由与偏好

- 常见任务形态自动路由。
- “少问/先问/直接做/先给方向”等偏好生效。
- 路由失败与降级提示。

### M3：可控记忆

- 本机偏好与项目记忆。
- 查看、删除与来源追溯。
- 最近任务恢复。

### M4：复杂任务治理

- 任务升级规则。
- 范围变化影响摘要与确认。
- 验收证据、发布确认和归档。

## 9. MVP 总体验收

- [ ] `byz` 启动后只问“你想让我帮你做什么？”。
- [ ] 单次研究、设计、写作任务不会被固定项目流程阻断。
- [ ] 用户能以自然语言改变 BYZ 的主动程度。
- [ ] 高影响操作会说明影响并等待确认。
- [ ] 用户可查看、删除与追溯本机记忆。
- [ ] 中断后能恢复最近上下文或待决事项。
- [ ] 默认输出不出现内部能力名称、推理过程或工具调用日志。
- [ ] 用户能理解何时需要自己决定，以及为什么。
