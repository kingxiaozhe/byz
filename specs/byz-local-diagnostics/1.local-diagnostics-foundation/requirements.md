# Local Diagnostics Foundation — 需求规格

## 概述

为 BYZ 增加默认本地、严格隐私白名单、可随时关闭的结构化诊断能力，并保证诊断故障永不影响主流程。

## 项目信息

- 项目名: pi-monorepo
- 架构类型: Node.js npm workspace monorepo；BYZ 是基于 Pi coding-agent runtime 的 CLI 产品层
- 交付形态: CLI / TUI
- 上下文范围: full

## 用户故事

- 作为 BYZ 用户，我希望 BYZ 只在本机记录低敏感度运行事实，以便排查故障而不泄露工作内容。
- 作为 BYZ 用户，我希望查看诊断状态和聚合摘要，以便快速识别高频错误、慢操作和重试。
- 作为 BYZ 用户，我希望随时关闭、临时增强或清除诊断，以便控制本地数据生命周期。
- 作为 BYZ 维护者，我希望诊断系统在任意故障下都让路给主流程，以便可观测性不会降低产品可靠性。

## 功能需求

1. [F-001] BYZ 必须提供基础诊断模式；该模式默认仅在本机开启，首次交互运行明确告知，用户可以执行 `byz diagnostics enable|disable` 修改状态。
2. [F-002] 基础模式只能记录 Schema 白名单中的固定枚举、布尔值、非负计数、版本和耗时区间；未知字段和自由文本必须在进入持久化队列前被拒绝。
3. [F-003] 所有模式都禁止记录 Prompt、模型回复、会话正文、文件内容、代码、Diff、工具参数或输出、用户名、项目名、绝对路径、URL、Cookie、Token、认证头、原始 Provider 请求响应和自由文本错误消息。
4. [F-004] BYZ 必须记录可用的应用启动/退出、Agent 运行、模型请求结果、HTTP 状态类别、工具名称/结果/耗时区间、重试或停止原因、归一化错误类别和诊断降级事件；事件不得包含调用 ID、会话 ID、模型 ID或项目标识。
5. [F-005] BYZ 必须提供临时详细模式 `byz diagnostics record --for <duration>` 和提前停止入口；该模式默认关闭、到期自动关闭，且不得放宽 F-003。
6. [F-006] BYZ 必须提供 `byz diagnostics status`，显示启用状态、模式、保留周期、容量上限、已用空间、最近可用写入状态、可观测的丢弃计数和降级状态。
7. [F-007] BYZ 必须提供 `byz diagnostics summary`，按时间范围聚合错误类别、慢操作、工具成功率、模型失败/超时、重试和 CM 工作流中断节点；命令只读取允许字段，样本不足时显示“数据不足”。
8. [F-008] BYZ 必须提供只读 `byz diagnostics doctor`，检查配置、目录权限、日志可读性、容量、轮转和 Schema 兼容性；不得自动修复或删除数据。
9. [F-009] BYZ 必须提供带确认的 `byz diagnostics clear`，删除诊断事件、摘要缓存和诊断状态；部分失败时列出未删除类别，不得报告全部成功。
10. [F-010] 本地事件默认保留 30 天且总量不超过 100 MB；达到任一上限后优先删除最旧数据，日志目录和文件仅当前用户可读。
11. [F-011] 运行期记录必须使用有界队列和非阻塞投递；队列满、写入慢、目录只读、磁盘满、文件损坏、锁冲突或写入器异常时允许丢弃事件，但不得等待、阻断或改变主流程结果。
12. [F-012] 多个 BYZ 进程必须写入各自的日志分片，避免通过共享写锁阻塞主流程；读取方必须容忍未完成尾行和单个损坏分片。
13. [F-013] AI 不得自动读取诊断事件；只有用户明确要求分析后才能读取脱敏摘要，读取原始事件需要额外明确授权。
14. [F-014] BYZ 不得上传诊断数据，也不得复用现有安装版本 ping 设置作为诊断上传授权。
15. [F-015] `diagnostics` 命令参数无效、持续时间越界或确认缺失时必须返回非零退出码和不含敏感内容的帮助信息。

## 非功能需求

- 性能: 基础诊断对启动时间的 p95 增量不超过 20ms；高频事件记录对对应操作的 p95 增量不超过 1%。
- 可靠性: 日志允许丢失；日志初始化、记录、轮转、读取和清理失败不得改变主流程返回值、异常、退出码、取消行为或进程退出时序。
- 安全: Schema、运行时验证和测试三层禁止敏感字段；诊断目录使用用户私有权限，不跟随不可信符号链接。
- 兼容性: 支持项目声明的 Node.js `>=22.19.0`，兼容 BYZ 的交互、print、JSON event 和 RPC 运行模式；首次告知不得污染非交互 stdout。
- 资源: 运行期队列必须有固定上限；后台记录资源不得使进程保持存活。

## 验收标准

- [ ] [AC-001] 在新的 HOME 中首次交互启动 BYZ，只显示一次本地诊断告知；print、JSON event、RPC 和 `--help` stdout 不出现该告知。
- [ ] [AC-002] 执行 `diagnostics enable|disable|status` 后，状态跨进程保持一致；禁用时运行期记录退化为 no-op，BYZ 主功能仍可用。
- [ ] [AC-003] 白名单事件可以落盘；加入任一未知字段、自由文本错误消息、路径、Prompt、工具参数或工具输出时，事件在排队前被拒绝且敏感值不出现在文件中。
- [ ] [AC-004] 一次成功和一次失败的工具执行只产生工具固定名称、结果和耗时区间；日志不含参数、结果、调用 ID、项目路径或会话 ID。
- [ ] [AC-005] 一次模型请求只产生允许的结果、HTTP 状态类别、耗时区间和停止/重试类别；日志不含 Prompt、回复、请求/响应正文、Header、Provider URL、模型 ID或响应 ID。
- [ ] [AC-006] `diagnostics record --for 30m` 开启临时详细模式，到期或提前停止后恢复基础模式；详细模式仍拒绝 F-003 的所有禁止内容。
- [ ] [AC-007] `diagnostics summary` 对有效事件给出带时间范围和样本量的聚合结果；损坏行、未知 Schema 和不完整尾行被计为不可用数据而不使命令崩溃。
- [ ] [AC-008] `diagnostics doctor` 在目录只读、文件损坏、容量超限和 Schema 不兼容时给出分类结果，不修改任何文件。
- [ ] [AC-009] `diagnostics clear` 未确认时不删除；确认后删除所有受管诊断数据；部分删除失败时返回非零且不声称全部成功。
- [ ] [AC-010] 超过 30 天或 100 MB 时仅清理受管目录中的最旧分片，不删除目录外文件，不跟随逃逸到受管目录外的符号链接。
- [ ] [AC-011] 注入目录只读、磁盘满、写入器抛错、队列满、Worker 启动失败和 Worker 意外退出后，BYZ 的业务返回值、业务异常、退出码和取消结果与禁用诊断时一致。
- [ ] [AC-012] 慢写入和持续满队列场景不会反压工具或模型请求；允许丢弃事件，并在恢复后尽力记录聚合丢弃计数。
- [ ] [AC-013] 两个并发 BYZ 进程不争用共享写锁，各自分片可独立读取；单进程异常退出不破坏另一进程分片。
- [ ] [AC-014] 进程正常退出或崩溃时不等待诊断队列排空；后台诊断资源不会单独保持进程存活。
- [ ] [AC-015] 默认运行 BYZ 时不会因诊断功能发出网络请求；`PI_TELEMETRY` 和安装版本 ping 设置不会启用诊断上传。
- [ ] [AC-016] 性能基准证明基础诊断满足启动 p95 增量不超过 20ms、高频记录 p95 增量不超过 1%；测量方法和原始结果进入测试证据。
- [ ] [AC-017] 用户未明确要求时，BYZ 和内置 AI 不读取原始诊断事件；常规分析入口只展示脱敏聚合摘要。
- [ ] [AC-018] `diagnostics` 的未知子命令、重复选项、无效持续时间和缺失确认均返回稳定非零退出码，不进入 Pi runtime。

## 依赖

- `packages/byz` 现有命令路由、内置扩展和构建复制流程。
- `packages/coding-agent` 现有 session、provider、agent、tool extension 事件。
- `packages/telemetry` 的显式 callback-based telemetry 契约和 Schema 元数据；现有 agent 高基数 Schema 不得未经投影直接持久化。
- CM Workflow 已有本地 `运行日志.jsonl` / 全局镜像；摘要只读取固定安全字段，不复制 `detail`、项目路径或正文。

## 开放问题

- 无。错误指纹默认采用错误类别与 BYZ 自有归一化模块位置，不包含消息、绝对路径、行号或第三方帧。
- 远程匿名遥测不在本需求范围内；未来如需增加，必须另立需求并重新取得用户授权。
