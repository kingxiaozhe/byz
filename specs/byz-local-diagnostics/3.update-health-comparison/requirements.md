# Update Health Comparison — 需求规格

## 概述

在 BYZ 更新前后生成本地健康基线并比较同类操作的聚合变化，只陈述相关变化，不错误宣称版本导致问题。

## 项目信息

- 项目名: pi-monorepo
- 架构类型: Node.js npm workspace monorepo；BYZ 自有更新命令
- 交付形态: CLI
- 上下文范围: full

| 日期 | 版本 | 说明 |
| --- | --- | --- |
| 2026-08-30 | v1 | 初始需求 |

## 用户故事

- 作为 BYZ 用户，我希望更新前自动保存本地聚合基线，以便更新后识别可能的异常变化。
- 作为 BYZ 用户，我希望比较结果说明样本量和环境差异，以便不会把网络或 Provider 变化误认为版本缺陷。
- 作为 BYZ 维护者，我希望更新诊断失败绝不阻止、改变或回滚更新主流程，以便诊断始终让路。

## 功能需求

1. [F-001] `byz update` 在执行更新命令前必须尽力生成只含聚合指标的本地基线；基线失败不得阻止、延迟或改变更新计划和退出码。
2. [F-002] 更新成功后必须记录旧版本、新版本和更新结果；更新命令失败时只记录固定失败类别，不记录命令输出或自由文本错误消息。
3. [F-003] 下一次使用新版本正常运行并产生足够样本后，BYZ 可以生成更新后健康摘要；不得为了等待样本保持进程存活或启动后台常驻服务。
4. [F-004] 比较只能使用相同事件类型、运行模式、工具类别和可比环境中的聚合指标；模型 ID、项目标识和用户标识不得进入比较键。
5. [F-005] Provider 类别、运行模式、Node/Bun 主版本、操作系统类别或关键诊断配置变化时，结果必须标记环境差异；不能直接给出版本退化结论。
6. [F-006] 每个比较项默认至少需要更新前和更新后各 20 个同类样本；任一侧不足时显示“数据不足”，不得计算或展示误导性百分比变化。
7. [F-007] 比较结果只能使用“改善”“持平”“观察到退化趋势”“数据不足”“环境不可比”，并明确声明观察相关性不证明版本因果关系。
8. [F-008] 更新健康数据必须遵守基础诊断的 30 天和 100 MB 上限、隐私白名单和本地不上传规则。
9. [F-009] 用户关闭诊断后，`byz update` 不生成基线或比较数据，更新行为与加入本功能前保持一致。
10. [F-010] 用户必须可以通过 `byz diagnostics summary` 查看最近更新比较，并通过 `diagnostics clear` 一并删除基线和比较结果。
11. [F-011] 更新比较不得自动回滚、阻止重启、自动提交 Issue 或上传诊断数据。

## 非功能需求

- 可靠性: 所有基线、记录和比较操作均为 best effort，更新主流程拥有绝对优先级。
- 隐私: 仅比较聚合指标和低基数环境类别，不保存项目、会话、模型或用户标识。
- 正确性: 明确区分观察相关性与因果关系；样本和环境不可比时不输出确定性结论。
- 兼容性: 保持 `byz update [--force]` 现有命令契约、npm 包身份校验和不降级策略。

## 验收标准

- [ ] [AC-001] 基线目录只读、磁盘满、写入器异常和诊断禁用时，`byz update` 的计划、执行命令、stdout/stderr 关键结果和退出码与无诊断功能时一致。
- [ ] [AC-002] 更新成功只记录旧版本、新版本和固定成功结果；更新失败只记录固定失败类别，日志不含 npm 命令输出、路径或错误消息。
- [ ] [AC-003] 更新前或更新后任一侧少于 20 个同类样本时，摘要显示“数据不足”且不展示百分比变化。
- [ ] [AC-004] 两侧样本充足且环境维度一致时，摘要按规定枚举显示改善、持平或观察到退化趋势，并显示两侧样本量。
- [ ] [AC-005] Provider 类别、运行模式、Node/Bun 主版本、操作系统类别或诊断配置变化时显示“环境不可比”或环境差异提示，不输出确定性版本退化结论。
- [ ] [AC-006] 所有比较结果包含“相关性不证明版本因果关系”的说明。
- [ ] [AC-007] 更新后比较在后续正常运行中按已有样本尽力生成，不等待样本、不创建常驻进程、不阻止 BYZ 退出。
- [ ] [AC-008] 关闭诊断后更新不创建基线、更新事件或比较结果，也不出现额外网络请求。
- [ ] [AC-009] `diagnostics summary` 可以展示最近可用比较；`diagnostics clear` 删除基线和比较结果后不再展示旧结论。
- [ ] [AC-010] 更新比较不触发自动回滚、自动 Issue、浏览器打开或任何诊断上传。
- [ ] [AC-011] 现有 `byz update` 的包身份校验、参数校验、不降级和 npm registry 固定端点测试保持通过。

## 依赖

- `1.local-diagnostics-foundation` 的聚合摘要、状态、保留和清除能力。
- `packages/byz/src/update.js` 现有更新计划与执行链路。

## 开放问题

- 无。初始阈值只用于显示趋势：错误率绝对增加至少 5 个百分点或耗时区间向更慢等级移动时标记“观察到退化趋势”；阈值未来变更必须更新规格并重新审批。
