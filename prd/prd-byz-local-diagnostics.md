# BYZ 本地诊断系统——产品需求文档

> 成熟度：L2 成熟 PRD
> 类型：B CLI / 开发者工具
> 核心原则：本地优先、隐私白名单、主流程优先
> 一句话：在不采集用户内容、不自动上传数据、不影响主流程的前提下，记录结构化运行事实，帮助用户和开发者发现故障、性能退化和版本更新问题。

## 1. 问题陈述

BYZ 当前拥有会话、调试、CM 工作流和 telemetry 基础能力，但数据彼此分散，无法系统回答工具失败率、性能瓶颈和版本退化等问题。同时，会话内容和代码具有较高隐私敏感性，不适合直接用于产品分析。

本系统通过本地结构化诊断数据发现：

- 高频错误与崩溃；
- 慢操作和重试；
- 工作流中断点；
- 更新前后的异常变化；
- 日志系统自身的降级状态。

## 2. 目标用户

| 角色 | 描述 | 主要诉求 |
| --- | --- | --- |
| BYZ 用户 | 在本地运行 BYZ 的最终用户 | 快速定位故障，确认更新后是否出现异常变化 |
| BYZ 开发者 | 维护和改进 BYZ 的开发者 | 根据用户主动提供的脱敏证据发现高频问题 |
| AI 编码助手 | 经用户明确授权后参与排障的助手 | 读取脱敏诊断摘要，辅助定位问题 |

## 3. 核心方案

复用现有 telemetry 契约，增加本地持久化、聚合分析、版本比较和诊断包导出能力。

采用两级数据：

1. **原始诊断事件**：仅保存在用户机器上，自动轮转；
2. **脱敏分析摘要**：用户可以检查并主动导出。

不建设默认远程上传服务。

## 4. 最高优先级约束

### NFR-001 非干扰原则

日志系统是旁路能力：

> 日志允许丢失，主流程不得因日志受损。

- 主流程不得等待日志写入、轮转、清理或分析；
- 队列满时丢弃日志，不得反压主流程；
- 日志异常不得改变业务返回值、异常、退出码或取消行为；
- 日志初始化失败不得阻止 BYZ 启动；
- 进程退出时不得为了日志完整性明显延迟退出；
- 日志关闭后使用 no-op 路径；
- 默认不进行任何诊断数据网络传输。

违反本条即视为功能不合格。

### NFR-002 隐私最小化

- 使用字段白名单，不使用“先记录全部内容，再事后脱敏”的模式；
- Prompt、模型回复、代码、文件内容、凭证、路径和工具内容在任何模式下都禁止记录；
- 诊断功能不得因用户授权导出而绕过禁止字段；
- 用户必须能够查看状态、关闭功能并清除数据。

## 5. 诊断模式

### 5.1 基础模式

- 默认本地开启，首次运行明确告知；
- 用户可以永久关闭；
- 只接受固定 Schema 中的枚举、布尔值、计数和耗时区间；
- 禁止自由文本和高基数字段。

### 5.2 临时详细模式

```bash
byz diagnostics record --for 30m
```

- 默认关闭；
- 必须由用户主动开启；
- 到期自动关闭；
- 仍禁止 Prompt、代码、路径、凭证、工具内容和原始请求响应。

## 6. 核心用户故事

### US-001 本地诊断

作为 BYZ 用户，我希望系统记录低敏感度的运行结果和性能指标，以便出现问题时能够获得证据，同时不泄露我的工作内容。

**验收标准：**

- [ ] 基础模式只记录固定 Schema 允许的字段；
- [ ] 默认不会发送任何诊断数据网络请求；
- [ ] 用户可以关闭本地诊断；
- [ ] 日志系统失败时主流程继续执行。

### US-002 问题概览

作为 BYZ 用户，我希望查看错误、慢操作、重试和中断排行，以便快速判断主要问题。

**验收标准：**

- [ ] 摘要包含时间范围和有效样本量；
- [ ] 摘要显示错误类别、慢操作、工具成功率、模型重试和工作流中断节点；
- [ ] 样本不足时明确显示“数据不足”；
- [ ] 摘要不包含原始事件内容和禁止字段。

### US-003 安全导出

作为 BYZ 用户，我希望预览并主动导出脱敏诊断包，以便提交给开发者分析。

**验收标准：**

- [ ] 导出前显示时间范围和字段种类；
- [ ] 导出必须经过用户确认；
- [ ] 导出前执行隐私检查；
- [ ] 检测到禁止字段时拒绝导出；
- [ ] 诊断包只生成在本地，不自动上传或提交 Issue。

### US-004 数据控制

作为 BYZ 用户，我希望查看诊断状态、调整保留策略并彻底删除数据，以便控制本地数据生命周期。

**验收标准：**

- [ ] 用户可以查看启用状态、模式、空间占用和降级状态；
- [ ] 用户可以关闭诊断；
- [ ] 用户可以确认后清除事件、摘要、缓存和运行状态；
- [ ] 清除部分失败时不得报告全部成功。

### US-005 更新比较

作为 BYZ 用户，我希望看到更新前后的健康状态变化，以便发现可能的版本退化。

**验收标准：**

- [ ] 只比较相同类型的操作；
- [ ] 配置、Provider 或运行模式变化时标记不可直接比较；
- [ ] 样本不足时显示“数据不足”；
- [ ] 结果只描述观察到的相关变化，不宣称版本造成问题。

## 7. 功能需求

### FR-001 本地采集

记录以下结构化事件：

- 应用启动和退出；
- 工具执行结果；
- 模型请求结果、耗时和重试；
- CM 工作流节点结果；
- 未捕获异常分类；
- 更新过程及健康检查。

### FR-002 隐私白名单

允许记录：

- BYZ、Node/Bun、操作系统版本；
- 固定功能、工具和工作流标识；
- 成功、失败、取消、超时；
- 耗时区间、计数、退出码；
- 归一化错误类别和安全指纹。

禁止记录：

- Prompt、模型回复、会话正文；
- 文件、代码、Diff；
- 工具参数和完整输出；
- 用户名、项目名、绝对路径；
- URL、Cookie、Token、认证头；
- 原始 Provider 请求和响应；
- 自由文本错误消息。

Schema 未声明的字段必须拒绝写入。

### FR-003 本地数据生命周期

- 默认保留 30 天；
- 默认最多占用 100 MB；
- 超限时优先删除最旧数据；
- 日志目录和文件仅当前用户可读；
- 磁盘满、权限错误或文件损坏时停止写入并降级；
- 并发进程不得造成主流程阻塞。

### FR-004 状态查看

```bash
byz diagnostics status
```

显示：

- 是否启用；
- 当前模式；
- 保留周期和空间上限；
- 已使用空间；
- 最近成功写入时间；
- 丢弃事件数量；
- 是否处于降级状态。

### FR-005 本地摘要

```bash
byz diagnostics summary
```

输出：

- 错误类别排行；
- 慢操作排行；
- 工具成功率；
- 模型重试和超时；
- 工作流中断节点；
- 数据不足提示。

摘要不得包含原始事件内容。

### FR-006 健康检查

```bash
byz diagnostics doctor
```

只读检查：

- 目录权限；
- 配置有效性；
- 文件可读性；
- 容量和轮转状态；
- Schema 版本兼容性。

默认不得自动修复或删除数据。

### FR-007 安全导出

```bash
byz diagnostics export
```

导出流程：

1. 显示时间范围和字段种类；
2. 执行隐私检查；
3. 用户确认；
4. 生成本地诊断包；
5. 不自动上传或提交 Issue。

检测到禁止字段时必须拒绝导出。

### FR-008 清除数据

```bash
byz diagnostics clear
```

- 删除事件、摘要、缓存和运行状态；
- 删除前要求用户确认；
- 完成后显示已删除范围；
- 清除失败时不得报告成功。

### FR-009 AI 访问边界

- AI 不得因为处于 BYZ 会话中就自动读取诊断文件；
- 用户明确要求分析时，默认只提供脱敏摘要；
- 读取原始本地事件需要额外明确授权；
- Prompt、代码等禁止数据不存在“授权后例外”。

### FR-010 更新比较

后续阶段支持：

- 更新前生成本地基线；
- 更新后执行健康检查；
- 只比较相同类型操作；
- 配置或 Provider 变化时标记不可直接比较；
- 样本不足时显示“数据不足”；
- 只报告相关变化，不宣称版本造成问题。

## 8. 非功能需求与验收标准

### AC-001 主流程隔离

- [ ] 日志目录只读时，BYZ 正常启动和执行；
- [ ] 磁盘满时，工具和模型请求结果不变；
- [ ] 写入器抛出异常时，业务异常和退出码不变；
- [ ] 队列满时丢弃事件，不阻塞调用方；
- [ ] 日志文件损坏时，BYZ 仍能启动；
- [ ] 多进程竞争时不得锁死主流程；
- [ ] 禁用日志时所有业务功能保持可用。

### AC-002 隐私

- [ ] 固定 Schema 不提供 Prompt、路径、代码或凭证字段；
- [ ] 未知字段被写入器拒绝；
- [ ] 原始错误消息不得写入基础日志；
- [ ] 导出包出现禁止字段时导出失败；
- [ ] 默认运行期间没有诊断数据网络请求。

### AC-003 数据控制

- [ ] 用户可以查看、关闭和清除诊断功能；
- [ ] 临时详细模式到期后自动关闭；
- [ ] 超过 30 天或 100 MB 的数据被轮转；
- [ ] 清除后不存在残留事件、摘要或索引。

### AC-004 性能

- [ ] 基础诊断对启动时间的 p95 增量不超过 20ms；
- [ ] 高频事件记录对对应操作的 p95 增量不超过 1%；
- [ ] 日志清理和分析不在主流程同步路径执行。

## 9. 边缘与异常状态

| 场景 | 处理 |
| --- | --- |
| 日志目录不可写 | 进入降级状态，主流程继续 |
| 磁盘空间不足 | 停止写入并丢弃事件 |
| 队列满 | 丢弃新事件并增加内存计数 |
| JSONL 尾部损坏 | 忽略坏记录，不阻止启动 |
| Schema 版本不兼容 | 保留旧文件，新建兼容日志 |
| 导出发现敏感字段 | 拒绝导出并说明类别 |
| 清除部分失败 | 报告未删除项，不声称全部成功 |
| 进程崩溃 | 尽力记录，不延迟或阻止退出 |

## 10. 风险与依赖

| 风险或依赖 | 影响 | 缓解措施 |
| --- | --- | --- |
| 诊断路径进入主流程关键路径 | 增加延迟或造成故障 | 有界队列、no-op 降级、故障注入测试 |
| 错误信息包含用户数据 | 隐私泄露 | 禁止自由文本，仅记录错误分类和安全指纹 |
| 版本比较被误解为因果关系 | 错误判断版本质量 | 标记样本量、环境差异和“仅相关”说明 |
| 多进程写入竞争 | 文件损坏或阻塞 | 写入不得持有阻塞主流程的锁，允许丢弃 |
| 日志无限增长 | 占用用户磁盘 | 30 天和 100 MB 双重上限 |
| telemetry 契约缺少持久化能力 | 需要新增本地适配层 | 复用既有契约，不修改业务语义 |

## 11. 里程碑

### MVP：可信采集

- 基础与临时诊断模式；
- 本地有界存储；
- `status`、`summary`、`doctor`、`clear`；
- 启动、模型、工具和异常事件；
- 非干扰与隐私测试。

### 第二阶段：安全诊断包

- `export`；
- 导出预览；
- 隐私检查报告。

### 第三阶段：版本健康比较

- 更新前后健康比较；
- 趋势和退化提示；
- 环境变化与数据不足判定。

## 12. 非目标

- 自动上传；
- 在线分析后台；
- 用户画像；
- 跨设备追踪；
- 自动提交 Issue；
- 默认远程匿名遥测；
- 自动读取会话正文；
- 保存 Prompt、代码、路径、工具参数或完整输出。

## 13. 待明确的问题

- 错误指纹的稳定归一化规则需在技术规格中确定，但不得包含绝对路径和自由文本错误消息；
- 版本比较的最低样本量需在技术规格中定义，默认建议同类操作至少 20 次；
- CM 项目日志与通用诊断日志只做汇总关联，不复制项目日志正文；
- 是否增加默认关闭的匿名聚合遥测，留到本地系统验证有效后重新评估。
